# AI 掼蛋训练空间 Product Architecture

> 当前产品方向：AI 能力测评 + Ace 教练诊断 + 专项训练推荐

## 1. 产品定位

AI 掼蛋训练空间是一个由 Ace AI 教练陪伴的掼蛋能力测评与专项训练系统。

它不是：

- 课程网站
- 棋牌工具
- 文章平台
- 规则百科
- 单纯刷题 App
- 数值成长游戏

它是：

- AI 教练陪练系统
- 掼蛋判断训练场
- 能力测评系统
- 训练诊断系统
- 专项训练推荐系统
- 长期能力提升产品

用户进入产品时，不应该感觉自己在浏览课程目录，也不应该感觉自己在做任务刷数值，而应该感觉自己进入了一个训练空间：

```txt
我能测试当前水平。
我有教练解释结果。
我知道强项和短板。
我能开始下一步训练。
我能通过复测确认提升。
```

北极星体验：

```txt
用户完成一次测试
↓
系统生成能力画像
↓
Ace 给出训练诊断
↓
用户进入专项训练
↓
用户再次测试
↓
系统展示能力提升
```

## 2. 核心产品架构

产品由四个核心系统组成：

```txt
AI 掼蛋训练空间
├── Ace 教练中心
├── 能力测评系统
├── 专项训练系统
└── 能力画像系统
```

Ace 教练中心：

- 产品的统一引导角色。
- 负责欢迎、讲解、反馈、纠错、复盘和下一步建议。
- 连接测评、训练和能力画像三个系统。

能力测评系统：

- 负责判断用户当前掼蛋水平。
- 通过测试题、残局判断和实战选择收集能力信号。
- 输出当前水平、强项、短板和测评结论。

专项训练系统：

- 负责把能力短板转成训练动作。
- 通过残局训练、判断练习和错题复训帮助用户改善具体能力点。
- 每次训练必须有 Ace 反馈和下一步建议。

能力画像系统：

- 负责让用户看见自己的能力结构。
- 展示当前水平、已掌握能力、待提升能力和训练建议。
- 把每次测试和训练转化成可理解的能力变化。

三者关系：

```txt
能力测评系统发现问题
专项训练系统改善问题
能力画像系统呈现变化
Ace 贯穿全流程
```

## 3. 能力测评系统设计

能力测评系统目标：

让用户快速知道自己当前掼蛋水平，以及最应该训练的能力点。

测评内容不以题库数量组织，而以能力维度组织。

核心模块：

- 当前水平
- Skill Assessment Bar
- 能力维度测试
- 测评结果
- Ace 诊断
- 复测入口

当前水平：

- 用自然语言表达，不用复杂分数墙。
- 示例：基础入门、稳定判断、进阶控牌、协同提升。
- 当前水平必须来自最近一次测试表现。

Skill Assessment Bar：

- 展示用户在关键能力维度上的当前状态。
- 蓝色表示系统分析。
- 绿色表示已掌握。
- 橙色表示待提升。
- 黄色表示 Ace 的关键建议。

能力维度：

- 牌权判断
- 炸弹时机
- 贡牌理解
- 队友配合
- 残局收尾
- 风险控制
- 过牌判断

测评结果：

- 先给结论，再解释原因。
- 每次只突出一个最重要短板。
- 测评结果必须导向训练建议。

Ace 诊断：

- 结构为：当前水平、主要问题、下一步建议。
- 文案短、清楚、可控。
- 不输出不可控的大段分析。

复测入口：

- 用户完成专项训练后，引导再次测试。
- 复测展示能力变化，而不是单次成绩刺激。

用户测评流程：

```txt
进入测评
↓
观察牌局
↓
做出判断
↓
完成若干题
↓
系统生成能力画像
↓
Ace 给出训练诊断
↓
进入推荐训练
```

## 4. 学习系统设计

学习系统目标：

让用户在最短时间理解一个可执行的掼蛋判断，并服务后续训练。

学习内容不以文章组织，而以能力点组织。

核心模块：

- 知识课程
- 能力路径
- 知识卡片
- 案例教学
- 小练习

知识课程：

- 一节课只讲一个知识点。
- 结构为：口诀、教练提示、牌局图解、错误示范、正确示范、小练习。
- 每节课控制在一分钟内完成。

能力路径：

- 按能力组织，而不是按文章分类。
- 示例：基础规则、牌权判断、炸弹时机、队友配合、残局收尾。
- 每条路径对应训练题和测评维度。

知识卡片：

- 用于快速复习。
- 内容短、明确、可记忆。
- 示例：`能压不等于该压。`

案例教学：

- 用真实牌局片段解释一个判断。
- 必须配合牌面组件或图解。
- Ace 只讲关键判断，不做长篇分析。

用户学习流程：

```txt
进入能力路径
↓
选择一个能力点
↓
Ace 给一句目标
↓
学习知识卡片
↓
看错误/正确案例
↓
完成小练习
↓
进入对应训练或复测
```

## 5. 专项训练系统设计

专项训练系统目标：

让用户在接近实战的情境里改善一个具体能力短板。

核心模块：

- 残局训练
- 推荐训练
- 实战判断
- 错误反馈
- 复盘系统
- 再次测试

残局训练：

- 产品核心训练玩法。
- 用户看到牌局、剩牌、选项和必要的时间约束。
- 训练的不是记忆，而是判断。

推荐训练：

- 来自测评结果和能力画像。
- 每次只推荐一个最重要训练方向。
- 包含推荐原因、训练目标、预计时间和开始按钮。

实战判断：

- 题目围绕真实出牌决策。
- 示例：是否炸、是否过、是否送队友、是否拆牌。
- 选项必须短，避免阅读负担。

错误反馈：

- Ace 指出错因和下一步。
- 反馈结构：结论、原因、行动建议。
- 连续错误时降低难度，引导回学习系统。

复盘系统：

- 训练结束后展示关键步骤。
- 每次复盘只强调一个最大问题。
- 复盘输出应转化成下一次训练建议。

再次测试：

- 专项训练后引导用户复测。
- 复测用于验证短板是否改善。
- 复测结果更新能力画像。

训练流程：

```txt
进入推荐训练
↓
观察牌局
↓
做出选择
↓
Ace 反馈
↓
查看复盘
↓
继续专项训练或再次测试
```

## 6. 能力画像系统设计

能力画像系统目标：

让用户清楚看见自己的掼蛋能力结构，而不是只看到抽象记录。

核心模块：

- 当前水平
- Ability Profile Card
- 已掌握能力
- 待提升能力
- 训练建议
- 测试历史

当前水平：

- 代表用户当前综合表现。
- 必须由测试结果生成。
- 不靠时间累计或完成次数堆出来。

Ability Profile Card：

- 展示当前水平、强项、短板、Ace 诊断。
- 必须能在手机首屏或第二屏快速读懂。
- 必须指向下一步训练。

已掌握能力：

- 代表用户表现稳定的能力点。
- 使用绿色。
- 示例：过牌判断稳定、残局收尾稳定。

待提升能力：

- 代表用户当前最需要训练的能力点。
- 使用橙色。
- 示例：炸弹时机过早、队友配合不足。

训练建议：

- 必须具体到一个训练主题。
- 示例：先练「主贡牌判断」，再复测「牌权判断」。
- 不能只说“继续努力”。

测试历史：

- 展示最近几次测试变化。
- 重点展示能力变化，不展示复杂排名。

能力提升公式：

```txt
能力提升 = 测试发现问题 + 专项训练改善问题 + 再次测试验证变化
```

## 7. 首页 Training Arena 信息架构

首页是训练空间，不是课程列表。

首屏：

```txt
Ace
当前测评状态
主行动按钮
```

设计目标：

- 用户一眼知道是否需要测试。
- 用户一眼看到 Ace 的关键建议。
- 用户可以立即开始测评或推荐训练。

首屏内容：

- Ace 欢迎和当前建议。
- 当前水平摘要。
- 主按钮：开始测评 / 开始推荐训练 / 再次测试。
- Skill Assessment Bar 简要展示。

第二屏：

```txt
能力画像
推荐训练
学习路径
```

设计目标：

- 展示用户为什么要练这一项。
- 把测评结果转化为训练行动。
- 让学习系统服务训练，而不是独立成课程目录。

第二屏内容：

- 能力画像入口：当前水平、强项、短板。
- 推荐训练入口：残局训练、专项练习、错题复训。
- 学习入口：知识课程、能力路径、知识卡片。

第三屏：

```txt
测试历史
训练记录
复测建议
```

设计目标：

- 展示长期能力变化。
- 帮助用户知道训练是否有效。
- 不制造数值压力。

第三屏内容：

- 最近测试结果。
- 已训练能力点。
- 待复测能力点。
- 后续可接 AI 个性化推荐。

## 8. 用户核心循环

核心循环：

```txt
测试
↓
能力画像
↓
专项训练
↓
再次测试
↓
能力提升
```

测试：

- 用户在牌局情境中做判断。
- 系统记录选择结果和能力信号。

能力画像：

- 系统生成当前水平、强项和短板。
- Ace 用短句解释结果。

专项训练：

- 用户进入最需要训练的能力点。
- 训练内容和短板直接对应。

再次测试：

- 用户验证训练是否有效。
- 系统更新能力画像。

能力提升：

- 用户看到自己在哪个能力点上变稳定。
- Ace 推荐下一步训练。

循环设计原则：

- 每次循环不超过 3 分钟。
- 每次循环必须有明确诊断或训练收获。
- 每次循环都要指向下一步行动。

## 9. V1 / V2 / V3 产品边界

V1：核心测评闭环。

必须做：

- 首页 Training Arena
- Ace 反馈
- 基础课程
- 残局训练
- 能力测评
- 当前水平
- Ability Profile Card
- Training Recommendation Card
- 本地测评和训练记录

先不做：

- 复杂能力雷达
- 好友互动
- 赛事活动
- 完整个性化 AI 实时陪练
- 复杂动画和数字教练

V2：专项训练与复测扩展。

增加：

- 测试历史
- 能力画像变化
- 复测建议
- 错题复训
- 更丰富的残局训练
- Ace 轻量动画反馈

目标：

- 增强训练闭环。
- 增强用户对自己能力变化的理解。
- 让用户知道每次训练改善了什么。

V3：AI 个性化训练空间。

增加：

- AI 实时陪练
- 个性化训练推荐
- 数字教练
- 自动复盘摘要
- 动态能力画像
- 动态训练内容

目标：

- 从固定内容训练升级为个性化训练系统。
- Ace 成为真正的 AI 掼蛋教练。

## 10. 与现有项目关系

已有功能需要保留：

- Next.js App Router 结构。
- 移动端优先体验。
- `CoachAvatar` 和 `CoachBubble`。
- 课程数据结构。
- 残局练习数据结构。
- 本地 progress 记录。
- PokerCard 和 PokerHand 组件规则。
- V1 不接真实 AI、不接数据库、不做复杂动画的边界。

需要升级：

- 首页从学习工具首页升级为 Training Arena。
- 课程入口从文章式卡片升级为能力路径节点。
- 练习页从单题 Demo 升级为残局训练模式。
- Coach 从 UI 气泡升级为贯穿流程的 Ace 教练中心。
- progress 从简单记录升级为本地测评记录、训练记录和能力画像状态。

未来扩展：

- 动态能力画像。
- 复测建议。
- 错题复训。
- AI 个性化推荐。
- Ace 动画和数字教练形态。
- 自动复盘摘要。

迁移原则：

```txt
不推翻现有 MVP。
先升级信息架构。
再升级视觉表现。
最后升级 AI 能力。
```

## 产品验收标准

每次版本迭代前检查：

1. 用户是否能一眼看到当前测评状态。
2. 用户是否能立刻开始测评或推荐训练。
3. Ace 是否贯穿测评、训练、反馈和诊断。
4. 每次训练是否有反馈和下一步建议。
5. 能力画像是否让用户看到强项和短板。
6. 首页是否像训练空间，而不是课程目录。
7. V1 是否保持简单可上线。
8. 新功能是否服务核心循环，而不是分散注意力。
