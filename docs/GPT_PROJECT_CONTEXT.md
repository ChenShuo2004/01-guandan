# 掼蛋 AI 教练项目上下文

这份文档用于让新的 GPT、Codex 线程或协作伙伴快速理解本项目。阅读完以后，应该能立刻知道这个产品为什么做、怎么做、现在做到哪里、下一步该推进什么。

## 1. 我的初心

我做的不是一个掼蛋文章站，也不是普通视频课。

这个项目的初心是：

> 做一个移动端优先的掼蛋 AI 学习工具，让用户在 30 秒找到答案，1 分钟理解技巧，下一局马上能用。

用户不是来读长文的，而是来解决真实牌局里的判断问题：

- 什么时候该炸？
- 什么时候不该炸？
- 队友快走完了该怎么送？
- 对手只剩 1 张该怎么拦？
- 自己牌很散该怎么脱手？
- 为什么这一局会输？

所以产品核心不是“内容”，而是“训练闭环”：

1. AI 教练给一句短提示。
2. 用户看一张牌局图或可控牌面。
3. 用户做一个选择。
4. 系统立刻反馈对错。
5. 用户看到正确打法和复盘。
6. 经验、等级、错题和收藏被记录下来。

第一版不追求大而全，先做出一个用户打开就能学、能练、能感到进步的 MVP。

## 2. 产品定位

产品名暂定：掼蛋 AI 教练。

一句话定位：

> 一个由 AI 教练、牌局图解、学习路径和残局训练组成的掼蛋移动端训练 App。

不是：

- 不是文章目录。
- 不是百科知识库。
- 不是短视频自动生成器。
- 不是复杂后台系统。
- 不是一开始就做登录、付费和真实 AI 分析。

是：

- 手机优先的学习工具。
- 一分钟一个知识点。
- 一题一个真实判断。
- 用成长路径替代文章分类。
- 用可控扑克牌组件替代不准确的 AI 扑克牌图片。
- 后续可以扩展到 AI 牌局分析、付费专题、会员错题本和私教复盘。

## 3. 目标用户

### 新手用户

他们不熟规则、不知道牌型、不知道为什么输。

产品要帮他们快速入门，看懂牌局，少犯低级错误。

### 中级用户

他们会打，但经常凭感觉出牌。

产品要帮他们学会判断局势，减少乱炸、乱顶、乱拆牌，提升配合。

### 高级用户

他们已经有经验，想提高胜率和稳定性。

产品后续要支持残局推演、牌权控制、队友配合和心理博弈。

## 4. V1 产品边界

V1 必做：

- 首页
- 学习路径页
- 知识点学习页
- 残局练习页
- 我的进度页
- AI 教练组件
- 扑克牌组件
- 本地学习进度、收藏和错题记录
- 数据驱动课程和残局题

V1 暂时不做：

- 登录注册
- 付费系统
- 排行榜

- 上传牌局截图分析
- 复杂后台管理系统
- 自动生成课程短视频

V1 需要预留：

- Supabase 用户系统
- AI 教练结构化分析接口
- 图片识别服务层
- 课程短视频字段
- 付费专题和会员权限

## 5. 核心学习体验

### 首页

目标是让用户知道今天该学什么、该练什么。

当前首页方向：

- AI 教练短句提醒
- 今日继续学习
- 今日残局入口
- 学习路径进度
- 专题横向滑动区
- 我的进度摘要

### 知识点学习

原则：一个页面只讲一个知识点。

标准结构：

1. 标题
2. 一句口诀
3. AI 教练提示
4. 核心图解或牌面案例
5. 错误示范
6. 正确示范
7. 小练习
8. 完成后进入练习

### 残局练习

原则：让用户在真实决策中训练。

标准结构：

1. 当前局面
2. 四家剩牌
3. 我的手牌
4. 三个选项
5. AI 教练反馈
6. 正确复盘步骤
7. 完成训练并记录经验

### 我的进度

目标是让用户看到成长和沉淀。

记录内容：

- 等级
- 经验值
- 连续学习天数
- 已完成课程
- 已完成残局
- 收藏课程
- 收藏题目
- 错题

## 6. 技术架构

当前技术栈：

- Next.js 14
- React 18
- TypeScript
- Tailwind CSS
- Framer Motion
- localStorage

当前目录规则：

```txt
app/          页面路由
components/   通用 UI、布局、AI 教练、扑克牌、练习组件
features/     学习、练习、进度等业务功能
content/      课程、题目、残局、学习路径
types/        类型定义
lib/          工具函数、存储、未来服务层
hooks/        通用 React hooks
assets/       素材 Manifest
docs/         产品、视觉、内容、动画和项目文档
```

架构原则：

- 页面只负责结构、数据读取和组件组合。
- 复杂业务逻辑放到 `features`、`hooks` 或 `lib`。
- 课程、题目、残局必须由 `content` 数据驱动。
- 类型统一放到 `types`。
- 牌面必须由 `PokerCard`、`PokerHand`、`PokerTable` 等前端组件渲染。
- 不把课程文案、题目选项、素材路径和动画逻辑硬编码在页面里。

## 9. 下一步优先级

最推荐的推进顺序：

1. 先确保 `lint`、`typecheck`、`build` 全部通过。
2. 用真实手机宽度检查首页、学习页、练习页、我的页。
3. 把“什么时候该炸”这一课打磨到可展示标准。
4. 扩展到 3 节课程和 3 道残局题，验证数据驱动是否顺手。
5. 完善收藏题、错题回顾和继续学习入口。
6. 再扩展到 24 节课程和 20 道残局题。
7. 最后再接真实 AI、Supabase、付费和素材生成。

短期最重要的 MVP 标准：

> 用户打开手机后，可以在 3 分钟内完成：看一课 → 做一题 → 得到反馈 → 增加经验。

## 10. 给 GPT 的协作要求

如果你是正在协作的新 GPT，请遵守：

- 目标是帮助 KAI 做出产品，不是炫技。
- Less Code, More Product。
- 能直接改就直接改，不要只给建议。
- 所有页面移动端优先，重点适配 390px 到 430px。
- 不要把它做成文章站。
- 不要生成准确扑克牌图片，准确牌面必须用前端组件。
- V1 不接数据库、登录、真实 AI 和付费。
- V1 不调用图片生成或动画 Skill。
- 新课程、新题目优先加到 `content`，不要硬编码在页面。
- 修改代码保持最小改动。
- 每完成一个独立功能后，运行 lint、typecheck、build，通过后再提交 Git Commit。

## 11. 一句话记住这个项目

这是一个移动端优先的掼蛋 AI 教练训练工具，不是内容站。第一版要先跑通“学一个知识点、做一道真实残局、得到 AI 教练反馈、记录进度”的训练闭环。
