# 当前产品体验规则

> 本文档只约束当前已经存在的记牌训练模式。
> Daily Training、课程路径、成长报告等内容目前不是开放用户流程，不能作为当前体验验收依据。

## 1. 当前体验目标

用户打开产品后，应快速进入训练，而不是浏览大量内容。

当前主流程：

~~~text
开场页 → 记牌训练入口 → 自动牌局 → 记牌测试 → 训练报告
~~~

当前产品的核心价值是：

- 观察牌局。
- 记忆关键牌。
- 观察真实牌面。
- 记忆关键牌数量和出现情况。
- 获得简短、及时的 Coach 提示。

## 2. 首页规则

当前 / 是 OpeningScene：

- 展示产品名称和一句简短说明。
- 提供进入 /practice 的主按钮。
- 不展示课程列表。
- 不展示 Daily Training。
- 不展示能力画像。
- 不展示真实用户等级和成长数据。

/practice 是训练入口页：

- 说明记牌训练是什么。
- 展示记牌训练的价值。
- 提供进入具体记牌训练的按钮。
- 当前不提供独立 /training 入口。
- 不把未开放的课程、路径、Profile 当成当前导航。

## 3. 记牌训练规则

记牌训练页面必须优先展示：

- 当前训练目标。
- 当前牌局或关键牌。
- 用户需要观察和记忆的内容。
- 当前测试或下一步动作。

交互要求：

- 用户先观察，再接受测试。
- 测试结果要立即反馈。
- 反馈要说明记对或记错的原因。
- 训练结束后给出明确完成状态。
- 不用长篇文章替代牌局和测试。

## 4. 牌局引擎规则

记牌训练内部牌局引擎必须优先展示：

- 当前牌桌。
- 用户需要观察的关键牌。
- 当前牌局推进状态。
- 已出牌和牌局上下文。
- 记牌测试入口和暂停状态。

交互要求：

- 只能通过牌组件展示准确牌面。
- 非法牌型不能提交。
- 测试回答后立即反馈。
- AI 行动必须推进牌局，不应让训练卡死。
- Coach 反馈短、具体、与当前牌局相关。
- 牌桌和手牌优先级高于 Coach 气泡。
- 用户始终能重新开始训练。

## 5. Coach 规则

当前 Coach 是本地规则驱动能力，不是真实模型。

Coach 可以：

- 提示当前牌局状态。
- 解释出牌是否合法。
- 指出用户当前动作的问题。
- 推荐一组牌或下一步动作。
- 在训练完成时给出总结。

Coach 不可以被描述为：

- 真实大模型教练。
- 自动分析用户历史的智能系统。
- 已经具备截图识别能力的 AI。
- 已经具备个性化成长报告的 AI。

文案规则：

- 优先一句结论。
- 再给一个原因。
- 最后给一个可执行建议。
- 避免长篇讲解。
- 不遮挡牌桌和用户手牌。

## 6. 导航规则

当前导航只承载已开放功能：

~~~text
记牌训练 → /practice
~~~

以下页面虽然存在代码，但当前被 middleware 重定向，不应出现在当前产品导航或验收标准中：

~~~text
/assessment
/coach
/complete
/growth-report
/history
/learning-path
/lessons
/paths
/profile
/design-system
~~~

## 7. 当前不做的体验

当前不要求：

- 每日任务推荐。
- 课程完成后自动进入关联残局。
- XP、等级、连续学习闭环。
- 训练历史。
- 学习路径解锁。
- 个人能力画像。
- 账号登录和云同步。
- 真实 AI 长文本对话。
- 多人在线对战。
- 支付和会员。

这些内容可以作为后续需求，但不能写入“当前已实现体验”。

## 8. 当前验收清单

### 入口

- / 能进入 /practice。
- /practice 能进入具体记牌训练。
- /practice 能进入具体记牌训练实例。

### 记牌训练

- 牌局正常推进。
- 关键牌追踪正常。
- 记牌测试可以操作。
- 结果有即时反馈。
- 训练可以完成或重新开始。

### 记牌训练牌局

- 牌面准确可见。
- 牌局能自动推进。
- 关键牌追踪正常。
- 测试点可以暂停牌局。
- 记牌问题可以回答。
- 回答后有正确/错误反馈。
- 训练可以继续或查看结果。

## 9. 修改原则

修改当前功能时：

1. 先保证 /、/practice、/practice/[practiceId] 不被破坏。
2. 不要把预留页面当成当前主流程。
3. 不要新增未实现的产品承诺。
4. 牌局功能优先复用现有牌组件和 gameStore。
5. 新增功能必须同步修改当前产品说明和路由状态。
