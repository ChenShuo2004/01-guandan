# AI 掼蛋教练 Character Visual Guide

## 1. 角色定位

角色名称：Ace

产品身份：AI 掼蛋教练。

Ace 是掼蛋 AI 学习平台的核心教练 IP，不是普通聊天助手，也不是单纯吉祥物。它代表产品的训练感、陪伴感和专业判断力。

用户认知：

- 用户打开产品时，看到的是一位固定教练，而不是一个随机 AI 工具。
- 用户答题、复盘、学习路径推进时，Ace 负责给短、准、可执行的反馈。
- 用户长期使用后，应自然形成认知：Ace 不是来聊天的，是来帮我打得更好的。

性格关键词：

- 友好
- 聪明
- 专业
- 耐心
- 短句
- 实战派
- 有一点幽默

与普通 AI 助手的区别：

- 普通 AI 助手回答问题，Ace 负责训练决策。
- 普通 AI 助手可以长篇解释，Ace 必须短句、清楚、可控。
- 普通 AI 助手没有固定人格资产，Ace 有稳定形象、表情、动作和语气。
- 普通 AI 助手被动响应，Ace 会在关键训练节点主动提示。

## 2. 角色视觉规范

必须固定的识别元素：

- 黄色方块头
- 蓝白教练外套
- 扑克牌元素
- 黑色椭圆眼睛
- 简洁卡通比例
- 亲和、明亮、无攻击性的表情

主色：

- Coach Yellow：用于头部和手部，是第一识别色。
- Coach Blue：用于袖子、外套边缘和科技感细节。
- Clean White：用于教练外套主体，表达专业、干净、学习感。

辅助色：

- Warm Brown：用于头发、内搭和阴影过渡。
- Card Red：用于扑克牌红桃、重点提示和少量情绪强调。
- Soft Shadow Gray：用于衣服折影、鞋底和卡片阴影。

材质：

- 头部：柔和塑胶或软质卡通材质，不能像金属。
- 外套：轻量运动教练服材质，有简洁折线，不做复杂纹理。
- 扑克牌：平滑白卡纸材质，牌面只作为角色道具，不作为真实训练牌面。
- 鞋子：简洁白色运动鞋，保持轻快感。

线条风格：

- 外轮廓清晰。
- 线条可以有轻微手绘感，但不能凌乱。
- 不使用复杂漫画排线。
- 小尺寸头像下仍然能看清头部、眼睛和外套。

光影风格：

- 明亮、温暖、柔和。
- 使用轻量体积感，让角色接近半 3D 卡通。
- 不使用强烈赛博霓虹。
- 不使用暗黑、压抑或写实电影光。
- 背景可以暖色，但 UI 内头像必须能适配浅色和深色界面。

比例规范：

- 头部大，占整体高度约 40% 到 50%。
- 身体短，整体偏可爱但不幼稚。
- 手部可以略大，方便表达挥手、指向、拿牌。
- 腿部简洁，不做复杂写实人体比例。
- 站姿重心稳定，适合做 UI 角标和动画循环。

## 3. 标准角色母版

未来生产图片、3D 建模和动画前，必须先建立标准母版。

正面：

- 用于 App 首页、头像、欢迎页、品牌展示。
- 要完整呈现黄色方块头、黑色眼睛、蓝白外套和扑克牌道具。
- 表情默认友好微笑。

45 度：

- 用于课程讲解、残局提示、右下角教练位。
- 最适合表现指向牌桌、拿牌、思考等动作。
- V1 和 V2 的主要 UI 视角应优先使用 45 度。

侧面：

- 用于指向牌桌、复盘分析、动画转身。
- 需要保持方块头厚度和头发形状一致。

背面：

- 用于 3D 建模和未来动画资产。
- 外套背部可以有简洁标识，但不应出现复杂 logo。

标准站姿：

- 双脚稳定站立。
- 一只手自然放下或持牌。
- 一只手可准备挥手或指向。
- 表情保持中性友好。
- 适合做所有动作的基础骨架。

## 4. 表情系统

idle 默认：

- 使用场景：首页待机、页面空闲、训练未开始。
- 视觉表现：轻微微笑，眼睛自然睁开。
- 用户心理目标：降低压力，让用户愿意开始。

happy 鼓励：

- 使用场景：答对、完成一个知识点、连续训练。
- 视觉表现：笑容更明显，眼睛弧度更开心。
- 用户心理目标：强化“我做对了”的即时反馈。

thinking 思考：

- 使用场景：用户犹豫、AI 分析中、轻提示前。
- 视觉表现：眼神聚焦，嘴部收起，可配合托腮动作。
- 用户心理目标：提醒用户先观察，不急着出牌。

warning 提醒：

- 使用场景：答错、高风险出牌、误用炸弹。
- 视觉表现：表情认真，但不能凶。
- 用户心理目标：让用户意识到风险，同时不产生挫败。

teaching 讲解：

- 使用场景：课程重点、牌理解释、规则提示。
- 视觉表现：嘴部轻微张开，眼神看向牌桌或重点区域。
- 用户心理目标：把注意力从角色转移到牌局判断。

celebrate 庆祝：

- 使用场景：完成今日训练、升级、连续学习达成。
- 视觉表现：大笑、举手、鼓掌或轻跳。
- 用户心理目标：让用户感到完成闭环，有动力继续练。

## 5. 动作库

V1 动作：

wave 欢迎：

- 用于首页、开始训练、首次进入学习路径。
- 动作幅度小，适合静态图或轻微动效。

point 指向：

- 用于讲解牌桌重点、指出正确选项、复盘关键步骤。
- 手势方向必须能与 UI 高亮区域配合。

thinking 思考：

- 用于等待用户判断、分析中、提示前。
- 可以表现为托腮、低头看牌或轻微眯眼。

warning 纠错：

- 用于答错和风险提示。
- 动作可以是轻轻抬手制止或指向正确选择。
- 禁止夸张摇头、嘲讽或攻击性手势。

happy 鼓励：

- 用于答对、完成一个小目标。
- 可以点赞、微笑或轻握拳。

V2 动作：

拿牌：

- 用于进入残局和课程牌例。
- 牌面只作为道具，不替代真实 `PokerCard` 组件。

翻牌：

- 用于题目揭晓、答案展示。
- 动作必须短，不影响用户继续操作。

鼓掌：

- 用于完成训练、连续正确。
- 不做长循环，避免干扰。

举讲解板：

- 用于课程总结、口诀提示。
- 讲解板文字应由前端渲染，不写死在图片里。

复盘分析：

- 用于错题回看和训练总结。
- 可以配合指向牌桌、时间线或重点卡片。

## 6. UI 使用规范

首页：

- Ace 出现在首页上半部分或桌面端右侧栏。
- 作用是欢迎和推荐今日训练。
- 文案最多两行。
- 不做全屏数字人欢迎页。

学习页：

- Ace 以 inline 教练气泡出现。
- 每个知识点只出现一次核心提示。
- 角色应指向牌面、口诀或错误/正确对比。
- 不遮挡课程主体图解。

残局页：

- 用户选择前，Ace 默认隐藏或只给轻提示。
- 用户答题后，Ace 出现在选项下方或反馈区。
- 纠错时强调下一步打法，不占据牌桌中心。
- 移动端不固定悬浮在会遮挡手牌的位置。

复盘页：

- Ace 出现在复盘总结顶部或关键步骤旁。
- 只讲一个最大问题和一个下一步训练建议。
- 表情应更冷静，少用庆祝。

小尺寸头像：

- 必须保留黄色方块头和黑色眼睛。
- 外套可简化，但蓝白识别必须存在。
- 扑克牌道具可省略，不能影响头像识别。

## 7. 禁止事项

禁止改变黄色方块头形象。

禁止随机换衣服。蓝白教练外套是标准制服，后续皮肤必须基于这个识别系统扩展。

禁止改变核心比例。不能变成长腿写实人，也不能变成普通圆头卡通。

禁止真人化。Ace 不是真人数字人，不做真实人脸、真实皮肤和写实五官。

禁止二次元化。不能变成日漫美少年、美少女或强二次元头像。

禁止过度科技化。不能用复杂机械装甲、赛博义眼、强霓虹替代当前亲和感。

禁止弱化扑克牌关联。角色必须和掼蛋、牌局、训练场景保持连接。

禁止在角色图片里生成准确牌局。真实训练牌面必须由前端牌组件渲染。

禁止让角色抢 UI 主体。Ace 是教练，不是页面主角；牌桌和训练任务永远优先。

禁止情绪过度。纠错不能凶，鼓励不能浮夸，庆祝不能打断训练节奏。

## 8. 未来扩展

V1：静态角色 + 简单动作。

- 使用当前形象作为标准方向。
- 建立头像、半身、全身、欢迎、指向、思考、纠错、鼓励等静态资产。
- 接入现有 CoachBubble 和 CoachAvatar 体系。
- 不做复杂动画，不做数字人。

V2：Lottie 动画。

- 为 wave、point、thinking、warning、happy 制作轻量循环或短动作。
- 动画时长控制在 0.5 秒到 1.5 秒。
- 支持移动端低成本加载。
- 动作只服务训练理解，不做装饰性表演。

V3：3D 数字教练。

- 基于标准母版做 3D 建模。
- 保留黄色方块头、蓝白外套、简洁比例。
- 支持更多角度和更自然动作。
- 仍然不做真人化数字人。
- 语音、AI 分析和个性化反馈必须遵守 Coach System 的结构化规则。

## 生产检查清单

每次生成或外包 Ace 角色资产前，必须检查：

1. 黄色方块头是否保留。
2. 蓝白教练外套是否保留。
3. 黑色眼睛是否保留。
4. 是否仍然像掼蛋教练，而不是普通 AI 吉祥物。
5. 动作是否对应 Coach State。
6. 是否适合移动端小尺寸显示。
7. 是否没有遮挡牌桌和训练内容。
8. 是否没有把真实训练牌面画死在图片里。
