# Ace Coach UI Integration

## 1. Coach UI 产品原则

Ace 是贯穿训练流程的智能教练，不是固定装饰头像。它的 UI 目标是帮助用户更快理解牌局、完成判断、获得反馈，而不是占据注意力。

核心原则：

```txt
牌局信息优先。
教练辅助决策。
```

教练什么时候出现：

- 用户进入首页，需要知道今天练什么。
- 用户进入课程，需要一句话理解知识点。
- 用户提交答案后，需要即时反馈。
- 用户答错后，需要知道错因和下一步。
- 用户完成训练后，需要总结成长。
- 用户进入我的页面，需要看到学习建议。

教练什么时候隐藏：

- 用户正在观察牌桌。
- 用户正在选择答案。
- 气泡会遮挡手牌、选项或关键牌面。
- 同一知识点已经提示过。
- 用户正在主动滑动复盘内容。

教练如何辅助用户：

- 用短句指出当前判断重点。
- 用状态区分欢迎、讲解、鼓励、纠错、思考、复盘。
- 用位置引导用户看牌桌、选项或复盘步骤。
- 用轻微动效强调状态变化。

如何避免打扰用户：

- 不做全局常驻大头像。
- 不在用户思考时连续弹气泡。
- 不在牌桌中央覆盖内容。
- 不输出长文本。
- 不把庆祝动画做成阻塞流程。

## 2. 页面级设计规范

### 首页

Ace 出现位置：

- 移动端：首屏内容流顶部，位于今日训练卡片之前。
- 桌面端：右侧栏或主内容右上区域。

默认状态：

- `state: welcome`
- `action: wave`

欢迎话术展示：

- 只显示一句主提示和一句补充。
- 例：`今天先练一题残局。`
- 补充：`重点看牌权。`

用户继续学习时如何引导：

- 如果有未完成课程，Ace 推荐继续课程。
- 如果今日已学习但未练习，Ace 推荐一道残局。
- 如果已经完成训练，Ace 给轻总结并推荐明天继续。

### 学习页面

课程讲解时 Ace 如何出现：

- 使用 inline 形式嵌入课程步骤。
- 每个知识点只出现一次关键教练提示。
- Ace 出现在知识点标题或牌面图解之后。

气泡位置：

- 优先放在相关牌面或图解下方。
- 不覆盖 PokerHand、CardTable 或练习选项。
- 移动端采用单列布局，气泡宽度跟随内容容器。

是否展开：

- 默认展示短气泡。
- 不做自动长展开。
- 需要更多解释时，由课程步骤单独承载，而不是让 Ace 长篇解释。

什么时候收起：

- 用户进入小练习区域后，讲解气泡不再重复出现。
- 用户滑过当前知识点后，不做悬浮跟随。
- 如果页面空间紧张，保留文字提示，弱化头像尺寸。

### 残局训练页面

答题前：

- Ace 默认隐藏，避免影响读牌。
- 如果需要提示，只出现 `thinking` 轻提示。
- 提示不能直接给答案。

思考中：

- 用户停留较久时，可以显示轻提示。
- 例：`先看队友剩几张。`
- 出现一次即可，不连续催促。

答错：

- 使用 `correcting` 状态。
- 位置在选项下方或反馈区。
- 先指出风险，再给下一步。
- 不遮挡正确答案和牌桌。

答对：

- 使用 `praise` 状态。
- 位置在选项下方或反馈区。
- 表扬具体行为，而不是空夸。
- 动效轻微，不阻塞进入复盘。

复盘：

- 使用 `review` 状态。
- Ace 出现在复盘步骤顶部或关键步骤旁。
- 每个复盘只强调一个最大问题。
- 每个步骤只给一句教练短评。

### 复盘页面

如何指出关键错误：

- 先展示关键牌局节点。
- Ace 在节点旁给一句结论。
- 错误原因放在下一句。
- 下一步建议放在最后。

示例：

```txt
这局输在太早交炸。
你失去了后手。
下次先看队友剩牌。
```

如何总结成长：

- 总结一个可迁移经验。
- 指向一个后续训练方向。
- 不同时列多个问题。

示例：

```txt
今天先记住牌权。
下一组练残局收尾。
```

### 我的页面

成长提醒：

- Ace 用低频提示表达学习进度。
- 重点展示连续训练、错题减少、等级提升。

学习建议：

- 根据已完成课程和错题类型给下一步。
- 不做压力型提醒。
- 不使用夸张激励语。

示例：

```txt
你最近常错炸弹时机。
下一组练这个。
```

## 3. Coach UI 组件规范

### CoachAvatar

使用场景：

- 所有 Coach 组件的基础形象。
- V1 作为占位头像。
- 小尺寸状态展示。

尺寸建议：

- 移动端默认 48px 到 64px。
- 列表或紧凑区域可用 40px。
- 不建议超过 96px，避免抢主内容。

出现条件：

- 需要强化角色存在感时出现。
- 紧凑反馈可只显示状态图标或小头像。

### CoachBubble

使用场景：

- 首页欢迎。
- 课程讲解。
- 答题反馈。
- 简短复盘提示。

尺寸建议：

- 宽度跟随父容器。
- 文案最多 2 到 3 行。
- 移动端左右留白至少 16px。

出现条件：

- 有明确 CoachMessage。
- 信息必须与当前任务相关。
- 不用于长文讲解。

### CoachCard

使用场景：

- 我的页面学习建议。
- 复盘总结。
- 今日训练推荐。

尺寸建议：

- 作为页面内容卡片出现。
- 可包含标题、短建议、按钮。
- 不嵌套其他大卡片。

出现条件：

- 内容需要承载一个完整行动建议。
- 例如：继续学习、去练错题、查看复盘。

### CoachFloating

使用场景：

- 未来实时陪练。
- 非牌桌密集页面的轻提示。
- 桌面端右下角辅助。

尺寸建议：

- 移动端谨慎使用，头像不超过 56px。
- 气泡不超过屏幕宽度的 70%。
- 必须避开底部导航和安全区。

出现条件：

- 不遮挡牌桌、手牌、选项、按钮。
- 提示可随时关闭或自动消失。
- V1 不作为主交互形式。

### CoachInline

使用场景：

- 课程步骤。
- 复盘步骤。
- 牌局重点解释。

尺寸建议：

- 单列内容内自然流式排布。
- 和课程卡片、牌面模块保持 12px 到 16px 间距。

出现条件：

- 当前内容需要教练解释。
- 解释和上下文强绑定。
- 最适合 V1。

## 4. 状态和 UI 映射

| State | 位置 | 组件 | 动画 | 持续时间 |
| --- | --- | --- | --- | --- |
| welcome | 首页顶部或桌面右侧栏 | CoachBubble / CoachCard | 淡入、轻微上移 | until-action |
| teaching | 课程步骤内 | CoachInline / CoachBubble | 淡入 | until-scroll |
| praise | 答题反馈区 | CoachBubble | 轻微缩放、成功色切换 | short |
| correcting | 答题反馈区、复盘节点 | CoachBubble / CoachInline | 轻微滑入、警示色切换 | until-action |
| thinking | 牌桌下方、提示区 | CoachFloating / CoachBubble | 淡入 | short |
| review | 复盘顶部或步骤旁 | CoachCard / CoachInline | 淡入 | until-action |

持续时间定义：

- `short`：约 2 到 4 秒，适合轻提示。
- `until-action`：直到用户点击下一步或切换区域。
- `until-scroll`：随内容自然滚动消失。

## 5. 移动端规则

适配范围：

- 以 390px 到 430px 宽度为基准。
- 桌面端只是扩展布局，不改变移动端核心体验。

最大宽度：

- CoachBubble 最大宽度跟随内容容器。
- 浮动气泡最大宽度不超过屏幕 70%。
- 复盘 CoachCard 不超过页面内容宽度。

气泡长度：

- 主文案最多 2 行优先。
- caption 最多 2 行。
- 超过 4 行时，应拆成课程内容或复盘步骤，不放在气泡里。

安全区域：

- 避开底部导航。
- 避开手机系统底部安全区。
- 避开主要操作按钮。
- 避开牌桌中心和手牌区域。

避免遮挡牌桌：

- 答题前不在牌桌上方悬浮大气泡。
- 牌面密集时使用下方反馈区。
- 指向和高亮应该服务牌面，不覆盖牌面。
- 如果头像与牌局冲突，优先隐藏头像，只保留文字反馈。

## 6. 动效规范

V1 使用 Framer Motion 的轻量微交互。

允许：

- 淡入
- 滑入
- 轻微缩放
- 状态切换
- 答对成功色反馈
- 答错警示色反馈

建议参数：

- 淡入：0.2s 到 0.35s。
- 滑入：距离 6px 到 12px。
- 缩放：0.98 到 1.02。
- 状态切换：不超过 0.3s。

禁止：

- 复杂角色动画。
- 长循环表演。
- 全屏庆祝动画。
- 阻塞用户操作的动画。
- 牌局时间轴动画和角色动画同时抢焦点。
- V1 调用图片生成或动画生成 Skill。

动效原则：

- 状态变化要被看见。
- 训练任务不能被打断。
- 低端手机不卡顿。

## 7. 用户流程示例

第一次进入 App：

```txt
首页
↓
Ace welcome：今天先练一题残局。
↓
选择水平
↓
Ace teaching：先从炸弹时机开始。
↓
推荐训练
↓
用户进入第一课
```

残局训练：

```txt
进入残局
↓
用户观察牌桌
↓
Ace 默认隐藏
↓
用户停留较久
↓
Ace thinking：先看队友剩几张。
↓
用户提交答案
↓
Ace praise 或 correcting
↓
进入复盘
↓
Ace review：这局重点是牌权。
```

课程学习：

```txt
进入课程
↓
展示一句口诀
↓
Ace teaching：能压不等于该压。
↓
展示错误示范
↓
展示正确示范
↓
小练习
↓
Ace 根据结果反馈
```

我的页面：

```txt
进入我的
↓
展示等级和连续学习
↓
Ace review：你最近常错炸弹时机。
↓
推荐下一组训练
```

## 8. V1 / V2 / V3 规划

V1：头像 + 气泡 + 简单状态。

- 复用现有 CoachAvatar 和 CoachBubble。
- 优先使用 CoachInline。
- 少量 CoachCard 用于总结和建议。
- 不做全局常驻浮动教练。
- 不做复杂动画。
- 不接实时 AI。

V2：动作动画。

- 接入 Ace 的 wave、point、thinking、warning、happy 轻动作。
- 使用 Lottie 或 SVG。
- 讲解时配合牌面高亮。
- 答题反馈加入短动作，但不阻塞流程。
- 桌面端可尝试 CoachFloating。

V3：实时 AI 陪练。

- 根据用户行为实时生成 CoachMessage。
- Ace 可在关键节点主动提示。
- 支持个性化学习建议。
- 支持错题模式和复盘摘要。
- 仍遵守短句、结构化、牌局优先原则。

## 交互验收清单

每次新增 Ace UI 前，检查：

1. 是否遮挡牌桌。
2. 是否遮挡手牌。
3. 是否遮挡选项和按钮。
4. 是否只讲一个重点。
5. 是否符合当前 CoachState。
6. 是否可以在 390px 宽度正常显示。
7. 是否可以被用户忽略或自然滚过。
8. 是否辅助了决策，而不是制造干扰。
